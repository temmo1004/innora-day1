# 數位履歷 / 數位名片

INNORA AI 人才培育 Day 1 用。使用者多半是**第一次碰程式的人**，不要用術語，不要要求他們懂 HTML。

## 鐵律

1. **不要編造事實。** 使用者沒給的經歷、學校、公司、數字，一律不准自己補。
   資訊不足就**問**，或在頁面上留一個明顯的佔位，不要用聽起來合理的假內容填滿。
2. **一次只問三個以內的問題。** 對方是新手，一次丟十個問題會嚇跑他。
3. **產出永遠是「單一 HTML 檔、可以直接用瀏覽器打開」。**
   不准用 React／Vue／build 工具／npm；CSS 寫在 `<style>` 裡；不連任何 CDN。
4. **不要用 lorem ipsum。** 沒內容就留空欄位並標示。
5. 每次交付後，**用一句話告訴他「現在可以改什麼」**，讓他知道下一步能做什麼。

## 開始前先收集（缺什麼就問）

| 欄位 | 說明 | 缺了怎麼辦 |
|---|---|---|
| 姓名 | | 必問 |
| 一句話介紹 | 「我是誰、我在做什麼」 | 必問 |
| 經歷 | 做過的事、待過的地方、學過的東西 | 必問，可以很短 |
| 想找什麼 | 他希望看完的人來找他談什麼 | 必問——這是整頁的目的 |
| 聯絡方式 | email／IG／LINE 擇一以上 | 必問 |
| 作品連結 | 有就放，沒有就不要放空區塊 | 可略 |
| 照片 | 有就用，沒有就用姓名首字做一個色塊頭像 | 可略 |
| 主色 | 沒指定就依他的氣質選一個，並說明為什麼選這個 | 可略 |

## 履歷頁的結構

由上而下，**不要多**：

1. **開頭區** — 姓名（大）、一句話介紹、聯絡按鈕
2. **關於我** — 三到五句，用他自己的話重寫，不要美化成公關稿
3. **經歷** — 時間、在哪、做了什麼、**做出什麼結果**（有數字放數字）
4. **作品** — 有才放
5. **我想找的** — 明確寫他希望被誰找到、談什麼
6. **頁尾** — 聯絡方式再一次

### 設計要求

- 手機優先。窄螢幕不准橫向捲動
- 一個主色 + 中性灰階，不要第三個顏色
- 內文 16px 以上、行高 1.7 以上
- 留白要夠，不要塞滿
- 不要漸層、不要陰影特效、不要進場動畫
- 深色模式：用 `prefers-color-scheme` 給一組對應色，背景色要明確寫出來

## 名片頁的結構

名片**不是履歷的縮小版**。它只有一個任務：**三秒鐘讓人記住這個人、並且能立刻聯絡到他**。

- 一頁到底，**不准捲動**
- 只有：姓名、一句話、聯絡方式、一顆「複製聯絡方式」的按鈕
- 手機打開就是全螢幕
- 允許一個小巧思（背景動態、hover 效果），但**只能一個**

## 交付方式

1. 先產出檔案，告訴他**檔案存在哪裡、怎麼打開**（用檔案總管／Finder 點兩下）
2. 用**三句話**說明你做了什麼設計決定，以及為什麼
3. 最後給他三個「你現在可以叫我改的東西」的具體例子，例如：
   - 「把主色改成墨綠色」
   - 「經歷第二項再展開講細一點」
   - 「加一個作品區塊，放我那個 IG 帳號」

## 部署（他要求時才做）

目標：GitHub Pages，讓他拿到一個公開網址。

**一步一步帶，每一步都要講清楚點哪裡、打什麼。** 他沒用過 GitHub。
遇到要登入／授權的畫面，停下來等他完成再繼續，不要自己猜。
拿到網址後，**請他用手機打開確認**——這才算完成。

## 常見狀況

- **他給的經歷很少**：不要因此把版面做得很空。減少區塊、放大字級、把僅有的內容做好，比硬撐六個區塊好。
- **他說「你幫我想」**：可以給選項讓他挑，但不要替他決定他是誰。
- **他要加很多花俏效果**：先做出來，再告訴他哪一個會讓載入變慢或在手機上壞掉，讓他自己選。
