STEP 0

Get your tools installed

Seven steps. One at a time. Raise your hand instead of struggling alone.

You are installing two things. They are two faces of the same tool:
a desktop app (visual, you click) and a terminal version (black screen, you type).
We use the desktop one this morning. This afternoon you'll see why the other exists.
First, this: that black terminal window cannot break your computer. If you mistype, it just prints a line of English you don't understand. Type it again. You will mistype many times today. That is normal.

① Get a ChatGPT account (the paid one)

  1. Open chatgpt.com
  2. Sign up — using your Google account is fastest, no new password to remember
  3. Click your name, bottom left → "Upgrade plan" → choose Plus → pay

Plus is about US$20 / month. This one is on you — it is not included in the course.

How you know it worked: back on chatgpt.com, there is a model selector in the top-left. If you can see it, you're upgraded.

② Open the terminal

Mac

  1. Press ⌘ + Space
  2. Type terminal
  3. Press Enter

Windows

  1. Press Win + X
  2. Choose Terminal
    (or PowerShell if that's all you see)

A window opens with a line of text and a blinking block. The blinking block is the cursor — it's waiting for you.

③ Paste one line to install the terminal version

Find the line for your computer, hit Copy, paste it into the terminal, press Enter.

MacInstall command 
curl -fsSL https://chatgpt.com/codex/install.sh | sh
WinInstall command 
powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 | iex"

How to paste: Mac ⌘ + V; Windows Ctrl + V or just right-click.

🔑 It may ask for your computer's login password. When you type it, nothing appears on screen — no dots, no stars. It looks frozen. That is normal. It is receiving your keystrokes. Type it and press Enter.

A wall of text scrolls by for a minute or two. When it stops and the cursor blinks again, it's done.

④ Check it really installed

BothCheck the version 
codex --version
Success looks like: it prints something like codex-cli 0.149.0. The numbers may differ — numbers means yes.
If it says "command not found": close the terminal completely and open a new one, then run codex --version again. That fixes it for nine people out of ten — a freshly installed tool needs a fresh window.

⑤ Sign in

BothStart and sign in 
codex
  1. It offers a few options — choose Sign in with ChatGPT (arrow keys to move, Enter to pick)
  2. Your browser opens by itself → sign in with the account from step ① → approve
  3. When it says you're signed in, go back to the terminal window
Success looks like: an input box at the bottom of the terminal. Type hello and press Enter — it answers you. English is fine here.

⑥ Now install the desktop version

BothInstall the desktop app 
codex app

It downloads and installs itself, then opens. From now on just launch it from Launchpad (Mac) or the Start menu (Windows) — no more typing.

⑦ Let it see your files

This is where most people get stuck.
The terminal version only sees the folder you are currently standing in. If you don't walk it there, it finds nothing.

Make a folder on your desktop called day1 (no spaces, English only). Then:

Mac: drag it in

Type cd then a space, then drag the folder into the terminal window — the path fills itself in. Press Enter.

Or: right-click the folder in Finder → Services → New Terminal at Folder

Windows: right-click

In File Explorer, right-click the folder → Open in Terminal.
That window already starts inside the folder.

If you type the path by hand: a folder name with spaces or non-English characters must be wrapped in double quotes, or it reads as two separate things.
❌ cd /Users/ninh/my project
✅ cd "/Users/ninh/my project"

Check where you are:

MacWhere am I 
pwd
WinWhere am I 
cd

The path it prints should end in day1. If it does, you're set — run codex in this window and it can see everything in that folder.

STEP 4

We break it. You fix it.

This is the real point. Making it is not impressive. Getting it back is.

  1. An instructor comes to your machine and breaks your page
  2. You use AI to fix it
  3. Whoever finishes goes and watches how their neighbour did it
SOSHow to describe a break 
My web page is broken.

What I see: (describe it plainly, e.g. everything turned into plain black text on white, the layout is gone)
Error message: (paste it if there is one, otherwise write "no error message")

First tell me what broke and why, then fix it.
I want to understand it, not just get a fixed file back.
If you can't describe what broke, the AI can't fix it —
this is the same thing as not getting the image you wanted this morning.
Two rules. Break either one and the exercise is wasted:
  1. No Ctrl+Z / ⌘Z. That isn't fixing it, that's running away.
  2. Don't ask the AI to "just redo the whole thing". Make it find what broke and fix only that.
Fixed means: the page looks like your design again, and you can say out loud what was broken. If you can't, ask the AI once more: "so what was the actual problem?"
STEP 5

Git and GitHub

Two words explained, then your card goes live.

What Git is

Version control

Every change saves a snapshot of how things were.
Broke it today? Go back to yesterday.

Backup

Your work isn't only on this laptop.
Lose the laptop, keep the files.

The place your work lives is called a repository — everyone says "repo". One project, one repo.

in plain words Git is the save function. GitHub is the cloud drive that holds the saves — and it also turns your page into a real URL.

Three questions (think first, then read)

QuestionAnswer
What is GitHub?Where the world's engineers keep code. Put your repo there and it stores it — and publishes it as a website.
Why must it be public to be visible?On a free account, GitHub Pages only publishes from a public repo. Make it private and the URL stops working.
Is there a way to keep it private and still show people?Yes, but every route costs something: paid plans can publish from private repos, or you use a different service. We'll think about this one together in class.
So: everything you put up today is visible to the whole world. National ID number, phone number, home address — do not put them there. Email or Instagram is enough.

Put your card online (get your URL)

No Git commands. All of it is clicking on a web page.

  1. Sign up for GitHub: open github.com → Sign up → email, password, pick a username.
    Your username becomes your URL. Choose well (lowercase, no underscores).
  2. Create a repo: top right + → New repository
    • Repository name: yourusername.github.io (exactly that, including .github.io)
    • Choose Public
    • Click Create repository
  3. Upload your file: Add file → Upload files → drag your page in → Commit changes at the bottom
    The file must be named index.html, or you'll get a blank page.
  4. Turn Pages on: Settings → Pages in the left menu → Source: Deploy from a branch → Branch: main and / (root) → Save
  5. Wait a bit, then open https://yourusername.github.io
It will not appear immediately. GitHub says up to 10 minutes. Seeing a 404 the first time is normal — get some water, come back, refresh.
This is the most important thing you do today You have a URL. Send it to the person next to you and ask them to open it on their phone.
They can open it — what you made today is on the internet.
SOSAsk it whenever you're stuck 
I'm putting a web page on GitHub Pages and I'm stuck.

Where I got to: (e.g. repo created, file uploaded)
What I see: (e.g. the URL shows 404)

Tell me step by step what to click and type next. I have never used GitHub.

What if someone wants to contact you?

Only if there's time left.

Your résumé is online.
Will anyone read it and want to reach you? — of course.
So if we wanted a form they fill in and you receive, what are our options?

Think: where do you already keep information?

Is it a way of storing things?
ExcelYes. Cells, columns, sortable — that is a table.
A text fileAlso yes. Just with no columns; everything mixed together.
A paper notebookAlso yes. But other people can't write into it and you can't search it.
so The difference isn't whether you can store things. It's who can write at the same time, whether you can find things instantly, and whether the data stays clean.
The thing built to solve those three is called a database.

Supabase

A cloud database with a free tier. You don't run a server; your page can write straight into it.

For your résumé, it means: someone leaves their contact details on your page, and you can see them in a dashboard.

We are not finishing this today. All you need from this section is why a database exists — actually building one comes later in the week.
CHEATSHEET

The five elements of a good prompt

  1. A clear goalWhat do you want? "A web-based snake game", not "a game"
  2. Concrete detailWhat does it look like? What are the rules? "Arrow keys to steer, it grows when it eats"
  3. FormatWhat should I get back? "One HTML file that opens in a browser"
  4. An example or referenceLike what? "Clean, the way Apple's site is clean"
  5. ConstraintsWhat are the limits? "No external frameworks, comment the code"

Four common mistakes

MistakeLooks likeWhy it fails
Too short"make a website"It doesn't know what you want, so it gives you the average
Too much at once"build a shop with 20 features…"Can't be done in one go → break it into stages
No context"make it blue"It doesn't know what to make blue
Vague adjectives"make it look good""Good" is subjective → describe it, or show a reference

Three metaphors (for when the code stops making sense)

HTML

The structure of a house
walls, doors, windows

CSS

The decoration
colour, furniture, style

JavaScript

The functions
light switches, opening the door
