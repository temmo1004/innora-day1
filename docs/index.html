STEP 0

先把工具裝起來

七個步驟，一步一步來。卡住就舉手，不要自己硬撐。

等一下你會裝兩個東西，它們是同一個工具的兩張臉：
桌面版（有畫面、用滑鼠點）跟 終端機版（黑底白字、用打字的）。
早上先用桌面版，下午你會知道為什麼需要另一個。
先講一句：終端機那個黑色視窗不會弄壞你的電腦。 打錯字它只會回你一行看不懂的英文，重打就好。今天你會打錯很多次，那是正常的。

① 先有一個 ChatGPT 帳號（要付費的那種）

  1. 瀏覽器打開 chatgpt.com
  2. 註冊 —— 用 Google 帳號登入最快，不用另外記密碼
  3. 登入後點左下角你的名字 → 「升級方案」→ 選 Plus → 刷卡

Plus 一個月約 US$20（折台幣約 600）。這筆是你自己付的，不含在學費裡。

做到這裡的驗收：回到 chatgpt.com 的對話畫面，左上角有一個可以切換模型的選單 —— 有看到就是升級成功了。

② 打開終端機

Mac

  1. 按 ⌘ + 空白鍵
  2. 打 terminal
  3. 按 Enter

Windows

  1. 按 Win + X
  2. 選「終端機」
    （沒有的話選 PowerShell）

會跳出一個視窗，裡面有一行英文字和一個一直在閃的方塊 —— 那個閃的就是游標，代表它在等你打字。

③ 貼一行指令，把終端機版裝起來

找到你自己電腦那一行，按「複製」，回到終端機貼上去，按 Enter。

Mac安裝指令 
curl -fsSL https://chatgpt.com/codex/install.sh | sh
Win安裝指令 
powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 | iex"

怎麼貼上：Mac 按 ⌘ + V；Windows 按 Ctrl + V 或直接按滑鼠右鍵。

🔑 它可能會問你電腦的開機密碼。 這時候你打字螢幕上不會有任何反應 —— 沒有黑點、沒有星號，看起來像當機。 那是正常的，它有收到。直接把密碼打完按 Enter。

接下來會跑出一大堆字，跑個一兩分鐘。字停下來、游標又開始閃 = 跑完了。

④ 確認真的裝好了

兩者皆同檢查版本 
codex --version
成功長這樣：它回你一行像 codex-cli 0.149.0 的字（數字不一定一樣，有數字就對了）。
如果回你「command not found」或「不是內部或外部命令」： 把終端機整個關掉，重新開一次，再打一次 codex --version。 九成的人這樣就好了 —— 剛裝好的東西要重開視窗才找得到。

⑤ 登入

兩者皆同啟動並登入 
codex
  1. 它會給你幾個選項，選 Sign in with ChatGPT（用上下鍵移動，Enter 選）
  2. 瀏覽器會自己跳出來 → 用步驟①那個帳號登入 → 按同意
  3. 看到「登入成功」就回到終端機視窗
成功長這樣：終端機下面出現一個輸入框，你可以在裡面直接打中文。 試著打「你好」按 Enter，它會回你話。

⑥ 再把桌面版裝起來

兩者皆同安裝桌面版 
codex app

它會自己下載安裝，裝完會自己打開。以後就從 Launchpad（Mac）或開始選單（Windows）點它就好，不用再打指令。

兩個都有了：桌面上一個有畫面的 App，終端機裡一個打字用的。同一個帳號，同一個工具。

⑦ 讓它看得到你的檔案

這一步最多人卡。
終端機版只看得到「你現在人在哪個資料夾」 —— 你沒帶它去，它就什麼都找不到。

先在桌面建一個資料夾，名字就叫 day1（不要用中文，不要有空格）。然後：

Mac：拖進去最快

在終端機打 cd 再加一個空格，然後把資料夾直接拖進終端機視窗 —— 路徑會自己跑出來。按 Enter。

或：在 Finder 對資料夾按右鍵 → 服務 → 新增位於資料夾的終端機視窗

Windows：右鍵最快

在檔案總管裡對資料夾按右鍵 → 選「在終端機中開啟」。
這樣開的視窗一開始就已經在那個資料夾裡了。

如果你硬要自己打路徑：資料夾名稱有空格或中文，整段路徑要用雙引號包起來，不然它會讀成兩個東西。
❌ cd /Users/ming/我的 專案
✅ cd "/Users/ming/我的 專案"

確認你人在對的地方：

Mac我現在在哪 
pwd
Win我現在在哪 
cd

它回給你的那串路徑，結尾應該是 day1。是的話就對了 —— 在這個視窗裡打 codex，它就看得到這個資料夾裡的東西。

你的數位履歷

不是 PDF。是一個別人打得開的網頁。

先準備素材（15 分鐘）

  • 你做過的事、學過的東西、待過的地方
  • 照片
  • 你 IG／作品／任何能證明你做過什麼的東西

第一次：故意隨便講

1先這樣丟給它 
幫我做一個簡歷

出來的東西，長得跟別人的一模一樣。這是故意的。

第二次：用 skill

skill 是什麼 一份寫好的「工作說明書」。裝上去之後，AI 做這件事就會照著那份說明書做 —— 不用你每次重講一遍要什麼。
它是一個檔案，可以下載、可以分享。能力是裝得上去的。

第一步：把 skill 裝起來。找你自己電腦那一行，複製、貼到終端機、按 Enter。

Mac安裝 digital-resume skill 
mkdir -p ~/.codex/skills/digital-resume && curl -fsSL https://temmo1004.github.io/innora-day1/skills/digital-resume/SKILL.md -o ~/.codex/skills/digital-resume/SKILL.md
Win安裝 digital-resume skill 
mkdir "$HOME\.codex\skills\digital-resume" -Force; irm https://temmo1004.github.io/innora-day1/skills/digital-resume/SKILL.md -OutFile "$HOME\.codex\skills\digital-resume\SKILL.md"
裝完一定要重開 Codex。 在 Codex 裡打 /exit 離開，再打一次 codex 進去 —— 不重開它讀不到新的 skill。

第二步：重新開一個新的對話，這次把 skill 的名字叫出來。

2這次點名要它用 skill 
用 digital-resume skill 幫我做一個簡歷
這次它的反應會完全不一樣。 它不會吐套版給你 —— 它會只問你三個問題，而且你沒講的東西它一個字都不會編。
怎麼知道它「沒吃到」skill？ 如果它一次問你七八個問題、或問你「要輸出成 Word 還是純文字」——那就是沒吃到。
解法：把 用 digital-resume skill 這幾個字加在句子最前面，再講一次。 光把檔案放進去它不一定會自己想到要用，你要叫得出它的名字。

第三步：把資料交給它。它問你的那三題，可以一題一題回，也可以直接用下面這張表一次講完。

STEP 4

我會把它弄壞。你要修回來。

這才是重點。做得出來不稀奇，壞掉救得回來才是能力。

  1. 我會走到你的電腦前，把你的網頁弄壞
  2. 你用 AI 把它修回來
  3. 修好的人去看隔壁怎麼修
SOS壞掉了怎麼講 
我的網頁壞掉了。

我看到的狀況是：（照實描述，例如：整個變成白底黑字，排版全跑掉了）
錯誤訊息：（有的話貼上來，沒有就寫「沒有錯誤訊息」）

請先告訴我「哪裡壞了、為什麼壞」，再幫我修。
我想看懂，不要只給我改好的檔案。
講不清楚壞在哪，AI 就修不好 ——
這跟你早上抽不到好圖，是同一件事。
兩條規則，違反就白做了：
  1. 不准按 Ctrl+Z／⌘Z 復原。那不是修好，那是逃走。
  2. 不准叫 AI「整份重做一次」。要它找出壞在哪，然後只修那裡。
修好的標準：頁面回到你原本設計的樣子，而且你講得出剛才是哪裡壞了。 講不出來就再問 AI 一次「所以剛剛到底是什麼問題？」
STEP 5

Git 與 GitHub

先講兩個字的意思，再把你的名片掛上網。

Git 是什麼

版本控制

每改一次就存一個「當時的樣子」。
今天改壞了，回到昨天那版就好。

備份

你的東西不只在這台電腦上。
筆電掉了，檔案還在。

你放東西的那個地方叫做「庫」（repository，大家都念 repo）。一個作品一個庫。

白話版 Git 是存檔功能，GitHub 是放存檔的雲端空間 —— 而且它順便幫你把網頁變成一個真的網址。

三個問題（先想再看答案）

問題答案
什麼是 GitHub？全世界工程師放程式碼的地方。你的庫放上去，它幫你保管、也幫你發布成網站。
為什麼要「公開」才看得到網站？免費帳號的 GitHub Pages 只能從公開的庫發布。庫設成私人，網址就打不開。
有沒有不公開、又能給人看的方式？有，但都要換條件：付費方案可以從私人庫發布；或改用別的服務。這題留到課堂上一起想。
所以今天你要放上去的東西，全世界都看得到。 身分證字號、電話、住家地址 —— 不要放。Email 或 IG 就夠了。

把名片掛上網（拿到你的網址）

不用學 Git 指令，全部用滑鼠在網頁上點。

  1. 註冊 GitHub：開 github.com → Sign up → 填 email、密碼、取一個帳號名。
    帳號名等一下會變成你的網址，取好一點（英文小寫，不要底線）。
  2. 建一個庫：右上角 + → New repository
    • Repository name 填：你的帳號名.github.io（一字不差，含 .github.io）
    • 選 Public
    • 按 Create repository
  3. 把檔案傳上去：Add file → Upload files → 把你的網頁檔直接拖進去 → 下面按 Commit changes
    檔名一定要叫 index.html，叫別的名字網址會是空白頁。
  4. 打開 Pages：Settings → 左邊 Pages → Source 選 Deploy from a branch → Branch 選 main 和 / (root) → Save
  5. 等一下下，然後打開 https://你的帳號名.github.io
不會馬上出現。官方說最久要 10 分鐘。 第一次先看到 404 是正常的 —— 去倒杯水，回來重新整理。
今天最重要的一件事完成了 你有一個網址。傳給旁邊的人，請他用手機打開。
他打得開 —— 你今天做的東西，已經在網路上了。

STEP 6

如果有人想聯絡你呢？

時間有剩才走這一段。

你的履歷放上去了。
有沒有人看完就想聯絡你？——肯定有。
那如果要做一個「他填一填、你就收得到」的系統，我們有什麼方式？

先想想：你平常都把資料存在哪？

是不是一種儲存方式？
Excel是。一格一格，有欄位，可以排序 —— 這其實就是一張表。
TXT 檔也是。只是沒有欄位，全部混在一起。
紙本筆記本也是。缺點是別人填不進來，你也搜尋不了。
所以 差別不在「能不能存」，在於 誰能同時寫、能不能馬上找、資料會不會亂掉。
專門解決這三件事的東西，叫做資料庫。

Supabase

一個免費就能用的雲端資料庫。你不用架伺服器，網頁可以直接把資料寫進去。

對你今天的履歷來說，它能做到的是：有人在你的頁面上留下聯絡方式，你在後台就看得到。

今天不會做完。這一段只要你聽懂「為什麼需要資料庫」就夠了 —— 真的動手做，是後面幾天的事。
速查

提示詞五大要素

  1. 明確的目標你要做什麼？「做一個網頁版貪食蛇」而不是「做個遊戲」
  2. 具體的細節它長什麼樣？有什麼規則？「用方向鍵控制，吃到食物會變長」
  3. 格式要求給我什麼樣的東西？「一個 HTML 檔，能直接用瀏覽器打開」
  4. 範例或參考像什麼一樣？「像 Apple 官網那樣的簡約風格」
  5. 約束條件有什麼限制？「不要用外部框架，程式碼要有註解」

四種常見錯誤

錯誤長這樣為什麼不行
過於簡短「寫個網站」AI 不知道你要什麼，只好給你平均值
過度複雜「做個電商，要有 20 個功能…」一次做不完 → 拆成階段
缺乏上下文「改成藍色」AI 不知道要改什麼東西
模糊形容詞「網站要好看」「好看」太主觀 → 給具體描述或參考圖
